AI in the hub: examples and cost

What each feature would write, where it would show, and what it costs per month with the owner's Anthropic API key. Every result is made on a schedule and cached, so a page or panel never waits on the API; with the API down or the cap reached, the hub shows what it had, marked stale, or nothing extra.

Watchtower's report, with what changed

public data

Input: the release notes between the old and new version of each updated image (the fork's report carries a changelog link). Haiku, about 4k tokens in per image.

Breaking: the database container needs a new image tag, and the machine-learning cache is rebuilt on first start. Back up the database first; plan 15 minutes.04:02

Why this one first

It sends only public text (release notes), it runs a few times a week, and it answers the one question the nightly report cannot: do I need to do anything? For Immich, which is pinned and updated by hand, it turns "check the release notes before updating" into a message that arrives on its own.

A model that is unsure says so: "could not read the release notes" instead of guessing. The plain report is always sent; the notes are an extra.

How it stays honest

Each story links to every source it was made from, and a tap opens the hub's reader for the original. The summary is one sentence, written only from the headlines and first lines it was given, in English or kept in Dutch as the source wrote it. Stories are grouped once per hour and cached, so the panel's Headlines screen reads the same list.

The cost is in the volume: hourly with Haiku stays under 30 cents a month, while the same job every half hour with Sonnet would be about EUR 10. That is the one feature where the model choice matters.

4. Alert explainer

Alerts, an error with a likely cause

house data, redacted

Input: the alert, the last 200 log lines of the container (emails, IPs and tokens replaced before sending), its restarts and memory. Sonnet, about 6k tokens in, only for ERROR alerts.

error
tracearr restarted 4 times in 10 minutes
since 14:12 · House
likely cause, by Claude
The database container ran out of disk space for its write-ahead log: every start ends with could not extend file: No space left on device. Volume 2 is at 99%.
  1. Free space on Volume 2 (the downloads folder is the largest, 1.8 TB).
  2. Then restart tracearr-db; tracearr follows by itself.

Boundaries

The explainer suggests; it never acts (the hub has no container control, and that stays). It is added to the alert in the hub and in Telegram a minute after the alert itself, so the alert is never held up. Redaction runs in the collector before anything leaves the NAS; it uses the same rules as the log viewer's privacy filter.

Two caps, so it cannot run away

In the hub: every answer's token usage is added up in SQLite. At 80% of the monthly cap a Telegram note; at 100% the hub stops calling until the 1st and pages fall back to what they had. /ask stops first, at 60%, so the scheduled features keep running.

At Anthropic: a monthly spend limit on the key's workspace in the Console, a little above the hub's cap, as a backstop if the hub's count is ever wrong.

Results are cached by a hash of their input, so a restart or a page reload never pays twice.
